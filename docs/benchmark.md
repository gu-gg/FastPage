# 性能与验证

## 测试入口

```bash
make                      # 共享库、静态库、C基准程序
make example              # 最小调用示例
make test                 # 不需要语料的独立向量、往返、边界与并发测试
make sanitize             # ASan + UBSan；单独目录构建，不产生速度成绩
make fetch                # 可选：获取官方Silesia 12文件
make verify CORPUS=corpus OUTPUT=runs/verify-01
make bench CORPUS=corpus CPU=0 ROUNDS=5 SECONDS=1.5 OUTPUT=runs/bench-01
```

也可以直接运行：

```bash
python3 tools/benchmark.py --corpus /path/to/silesia --cpu 0 \
    --rounds 5 --seconds 1.5 --output runs/bench-02
```

`--verify-only` 执行完整语料的正序与逆序解码校验，不计时。语料目录可以位于项目外；工具只读取12个指定文件并核对大小和MD5，忽略目录中的其他文件。运行输出目录必须是新的，失败或成功的旧结果都不会被覆盖。

## 计时口径

1. 固定一个允许使用的CPU，单线程测量。CPU0不一定在所有容器的允许集合内，可用 `taskset -pc $$` 查看当前允许CPU。
2. 语料读取、内存分配、哈希校验、构建和正确性比对均在计时区间外。
3. 每个文件分别切为4096字节页，保留文件末尾不足4096字节的页；不跨文件拼页。
4. 每轮在独立进程中载入库。所有页通过同一套公开编解码函数指针，包括内部RAW回退页。
5. 每个方向先执行一次完整语料预热，以预热时间估算循环次数。次数向上取整，最少1次、最多64次。`--seconds` 是校准目标，不保证每个实际样本恰好或至少持续这么久。
6. 奇数轮先压缩、偶数轮先解码；每轮均保存两个方向。压缩测试结束后重新解码校验，解码结果也做逐字节校验。
7. 同时记录单调墙钟和线程CPU时间，以墙钟MB/s中位数为主要结果。MB/s为十进制，每秒处理的原始字节数除以1,000,000；解码吞吐同样按还原字节计。

默认五轮共10个速度样本，全部保留。编码工作量含每页内部搜索表初始化及RAW回退复制，解码含每页格式判别；测试不含外层存储、页目录、调度或内核集成成本。

## 内存布局和空间统计

输入页引用内存中的完整文件；压缩输出每页使用5120字节对齐槽，解码输出每页间隔4096字节。整套基准的缓冲约占690 MB，建议至少1 GiB可用内存。槽宽用于方便独立访问，不计入压缩率，也不代表实际产品内存池的分配方案。

```text
压缩比 = 全部原始字节 / 全部保存载荷字节
空间节省率 = 1 - 全部保存载荷字节 / 全部原始字节
```

保存载荷包含RAW页和页内元数据，不包含调用方页目录、分配器对齐、校验和或容量预留。

## 输出与结束判断

成功条件是进程退出码0，且输出 `status.json` 中 `state` 为 `completed`。失败时查看该状态文件、构建日志和对应轮的错误日志；不要使用部分样本作为完整测试结果。

结果目录保存原始JSONL样本、每轮输出、`summary.json`、`REPORT.md`、环境记录、构建命令和源码/二进制哈希。测量期间若源码或产物变化，测试应报错。新的编译器、编译参数或机器都应另跑一个目录。

避免同时运行编译、sanitizer或其他CPU重任务。CPU绑核不能消除虚拟机调度和主机竞争，线程CPU/墙钟比例仅是辅助信息。虚拟桌面结果不代表裸机吞吐，本工具也不根据主频自动外推验收成绩。

## 正确性覆盖

| 入口 | 内容 |
|---|---|
| `verify_vectors` | 67,483个独立解码向量；数值字段逐位构造，LZ逐字节还原，精确大小分配 |
| `verify_roundtrip` | 13类合成输入覆盖全部1～4096长度，共53,248次往返；10,000次损坏/任意输入 |
| `verify_guards` | 960次前后保护页往返、410次调用历史独立性、512次并发检查，以及无效尺寸拒绝 |
| `make verify` | 完整12文件、51,746页；编码、正序解码、逆序解码和逐字节比对 |

损坏输入检查要求有界访问，并不要求所有变异数据都被拒绝；该格式没有校验和。`make sanitize` 在独立 `build/sanitize/` 目录运行上述合成测试，启用地址与未定义行为检查；为兼容受跟踪运行环境，LeakSanitizer关闭。完整语料也可追加：

```bash
python3 tools/fetch_corpus.py /path/to/silesia --verify-only
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 \
    build/sanitize/verify_roundtrip /path/to/silesia
```
